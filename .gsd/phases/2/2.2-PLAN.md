# Plan 2.2: Form Gatekeeper & Validation

## Objective
Implement the initial user experience requiring users to submit valid information (Name, Email, optional ID) before they can connect their wallet and access voting functionality.

## Context
- .gsd/SPEC.md
- Phase 1 decisions restricting user data from the blockchain.

## Tasks

<task type="auto">
  <name>Develop User Information Form</name>
  <files>
    - frontend/src/components/RegistrationForm.tsx
  </files>
  <action>
    - Create a clean, responsive `RegistrationForm.tsx` functional component using Tailwind for layout.
    - Include input fields for Name (required), Email (required), and ID (optional).
    - Implement basic form validation functionality (e.g., checking if name exists and email format is valid).
    - Manage local component state to handle input changes and submission events.
  </action>
  <verify>cd frontend && npm run build</verify>
  <done>Component logic handles validation properly and form UI renders functionally without breaking the build.</done>
</task>

<task type="auto">
  <name>Implement Conditional Rendering Gatekeeper</name>
  <files>
    - frontend/src/App.tsx
  </files>
  <action>
    - Architect conditional rendering state logic in `App.tsx` handling the primary UX flow.
    - State 1: Show `RegistrationForm`.
    - State 2 (Upon successful form submission): Show Wallet Connection button (`useConnect`).
    - State 3 (Upon Wallet Connection): Access granted to Voting Interface.
    - Do not allow wallet connection to persist/affect state if the form hasn't been submitted yet.
  </action>
  <verify>cd frontend && npm run build</verify>
  <done>User flow correctly isolates authentication flow: Form -> Connect Wallet -> Authed Application.</done>
</task>

## Success Criteria
- [ ] `RegistrationForm` component captures and validates data locally.
- [ ] Wallet connection is impossible or hidden until form submission is successful.
- [ ] UI provides clean visual feedback using Tailwind during these step transitions.
